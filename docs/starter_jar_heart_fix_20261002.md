## 心脏机制与数值

旧计数器699920～699927不在 EFID_common 分配的旗标范围内。
之前的 Python 模拟用集合表示旗标，默认任意编号都可写入，因此未发现这一点。
按分配范围限制写入后，旧程序在1/2/127/128/181场击败案例都无法得到小首领档位。
本次迁移到已分配的890992～890999，并替换旧事件扩展尾部，避免在旧 restart 后
再追加一个永远无法运行的扩展。前72条追忆刷新指令逐字保留。

旗标证据为 soulsmods 的 EventParam 原始数据，来源及完整文件哈希见
`data/heart_flag_allocation_reference.md`。另核对 vawser/ER-Documentation
的 `Info - Event Flags - Dump.txt`，同样列有890000起的1000个全局旗标。
对实际 v0.10.12 包内全部27个事件文件检查了指令实参及批量设置旗标区间，
未发现新八个编号的引用/范围冲突；其中26个KRAK文件使用官方作者
oozextract的CLI独立解码，commit `5ff5dc14be82160ab2c605dd844a46ba46e52d43`。
这属于静态根因判断及模型复现，不能代替游戏实测。
