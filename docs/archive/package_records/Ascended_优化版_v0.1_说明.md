# Ascended 优化版 v0.1：FP 消耗与一处事件引用

这是基于你上传的 Ascended 原包制作的第一版。**游戏内效果尚未实测**；请备份存档与原 MOD 文件，在游戏现有的离线 MOD 启动方式下测试。

## 改动规则

对 Ascended 中已有的 FP 消耗，只在其超过阈值时降低为 `min(Ascended 原值, max(保底 FP, 2 × 官方 1.17.1 对应值))`。法术、祷告的保底 FP 为 8；战技 L2/R1/R2 为 10。无对应原版行、负值和战技 9999 禁用值不动；其他字段、行和文件不动。官方 1.17.1 数据只用于计算目标数字，没有混入 Ascended 的 1.16 参数结构。

| 参数字段 | 中文含义 | 本版修改项数 |
|---|---|---:|
| `Magic.mp` | 基础施法 FP 消耗 | 176 |
| `Magic.mp_charge` | 蓄力时 FP 消耗 | 93 |
| `SwordArtsParam.useMagicPoint_L2` | 战技 L2 FP 消耗 | 232 |
| `SwordArtsParam.useMagicPoint_R1` | 战技衔接 R1 FP 消耗 | 22 |
| `SwordArtsParam.useMagicPoint_R2` | 战技衔接 R2 FP 消耗 | 58 |

共修改 **581 个参数值**（底层 649 个字节）。示例：辉石魔砾基础消耗 41 → 14；狮子斩 L2 80 → 40；光之米凯拉 2000 → 96。全部条目见附带 CSV，含英文名称和中文名称。

事件 `common.emevd.dcx` 中，4935 号事件有一处给玩家施加 `530373` 效果的指令；Ascended 的 `SpEffectParam` 不存在该 ID，而前后连续效果是 `530272`、`530274` 且 `530273` 存在，因此修正为 `530273`。只改这一条指令的一个参数。

## 安装与回退

1. 先备份当前存档，以及原始 Ascended 文件夹，尤其是 `ModEngine/mod/regulation.bin`、`ModEngine/mod/event/common.emevd.dcx`。不覆盖游戏本体的原版文件。
2. 如果此前把 Ascended 解压为一个文件夹，将“小补丁”压缩包解压并覆盖到该文件夹根目录，即包含 `ModEngine` 的那个目录；压缩包还包含根目录那份 `regulation.bin`。
3. 如果已经单独把 `ModEngine/mod` 部署到了游戏旁边，可仅把补丁中的 `ModEngine/mod/regulation.bin` 和 `ModEngine/mod/event/common.emevd.dcx` 覆盖到对应位置。
4. 也可使用“完整包”代替原 Ascended 文件夹。沿用你此前能启动 MOD 的离线启动方式。
5. 出问题时恢复刚才备份的两份文件（若使用根目录 `regulation.bin`，也一起恢复），或直接还原原始 Ascended 压缩包。

## 游戏内验收

在同一存档、同样蓝条与装备条件下记录施法前后 FP：普通辉石魔砾、可蓄力法术、一种高成本祷告；记录狮子斩及带 R1/R2 衔接的战技的每次消耗。再走一段你熟悉的 Boss／地图流程，核对技能是否正常触发、敌人和进度是否正常。之后反馈哪种 Build 仍难以维持输出、具体地点和预期，我据此做下一轮有针对性的调整。

## 当前边界

Ascended 包内参数版本为 1.16，作为数值参考的官方参数为 1.17.1；本包仍以 Ascended 1.16 为底。静态检查可以验证压缩、加密、表结构与实际更改范围，但不能证明游戏 1.17.1 中正常加载，也不能替代实机测试。地图、动画、敌人血量与进度事件目前保留为 Ascended 原值；如后续发现这些系统的联动过密，再评估吸收其优点独立制作 MOD。
